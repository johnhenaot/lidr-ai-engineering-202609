# Agent Guidelines

## Code Style & Cleanliness

- **No internal comments or docstrings:** Do not explain internal code with inline comments or docstrings.
- **Self-explanatory code:** Express intent through precise naming, small cohesive abstractions, and obvious data flow.
- **Specification via tests:** Document requirements, edge cases, and expected behavior through focused unit tests, not prose.
- **Concise test docstrings:** Test functions may carry a single-line, phrase-style docstring defining the exact unit behavior under test.
